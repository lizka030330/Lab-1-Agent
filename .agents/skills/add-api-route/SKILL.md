# Додати API-маршрут

Назва маршруту `<назва>` — малі латинські літери, цифри, дефіси (наприклад, `health`).

## Кроки

1. Спершу контракт: `src/<назва>.ts` зі схемою zod для відповіді. Тип виводь зі схеми (`z.infer`), а не пиши вручну.
2. Потім тест: `tests/<назва>.test.ts` імпортує обробник відносним шляхом `../app/api/<назва>/route` і перевіряє статус та відповідність схемі. Тест не ходить у мережу.
3. Лише тепер обробник: `app/api/<назва>/route.ts` експортує функцію HTTP-методу (`GET`, `POST` тощо) і відповідає через `Response.json(...)`. Схему імпортуй відносним шляхом (`../../../src/<назва>`), а не через аліас `@/`: `vitest.config.ts` проєкту цього аліасу не знає, і `npm test` впаде.
4. Запусти `npm test` і `npm run typecheck`.
5. Запусти з кореня репозиторію перевірку цієї навички: `node .claude/skills/add-api-route/scripts/check-route.mjs <назва>` (у копії шлях інший: `.agents/skills/add-api-route/scripts/check-route.mjs`).
6. Не звітуй «готово», поки `check-route.mjs` не повернув код 0, а `npm test` не зелений. Якщо скрипт повернув 1 — виправ те, що він надрукував у рядках `FAIL`, і запусти знову.

## Межі

- Не чіпай `.env*` і `package.json`: нову залежність додає людина.
- Загальні правила проєкту — в `AGENTS.md`; тут лише ця процедура.
