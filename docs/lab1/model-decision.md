`qwen3:4b` → `qwen3:4b-instruct` (та сама родина Qwen3 і той самий розмір 4B, але instruct-версія без режиму міркувань).

## Чому

На задачі `/api/health` з кроку 08 `qwen3:4b` щоразу витрачала весь ліміт виходу (`max_tokens` = 2048) на приховані міркування і не встигала відповісти: журнал Ollama показав 11 кроків поспіль по ~53 с, текстової відповіді не було. Ні `/no_think` у системному промпті, ні `thinking: {"type":"disabled"}` цього не прибрали (перевірено прямими запитами до `/v1/messages`). Instruct-версія відповідає одразу.

## Ризики

- **Дата зняття.** У `src/models.ts` для ролі `local` поля `retiresNotBefore` немає: модель лежить локально в Ollama, і завантажена копія не зникне до захисту, навіть якщо тег приберуть із бібліотеки Ollama. Для порівняння: в реєстрі є хмарна модель із `retiresNotBefore: '2026-10-15'` (рядок 132) — її варто перевірити перед захистом, якщо використовувати.
- **Політика даних.** Локальна модель не передає код нікуди за межі ноутбука — це перевага перед безкоштовними хмарними рівнями, де запити можуть використовуватися для покращення продуктів.
- **Якість.** Схему виходу instruct-модель проходить стабільно, але це перевіряє форму, а не зміст: на базовому коміті (`lab1/health-loop`) вона запропонувала робочий `route.ts` з невикористаними імпортами та імпортом через `@/`, а в окремих прогонах повертала лише незмінений `src/health.ts`. Мала модель — для дешевих і приватних прогонів, не для фінальних рішень без перевірки тестами.
- **Відтворюваність кроку 07.** Виміри кешу в `docs/lab1/cost.md` (розділ 2) і множник ua/en зроблено на `qwen3:4b`; вони лишаються чинними для тієї моделі й підписані її назвою.
