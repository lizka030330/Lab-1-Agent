| Артефакт | OpenCode | Codex |
|---|---|---|
| AGENTS.md | **Працює без змін.** OpenCode читає `AGENTS.md` у корені репозиторію і дотримується правил про перевірки, межі та дозволи. | **Працює без змін.** Codex використовує `AGENTS.md` у корені репозиторію як інструкції для роботи з проєктом. |
| Режим плану | **Потрібна адаптація:** агент Plan вмикається клавішею `Tab`; після схвалення плану для реалізації треба перейти в Build. Обмеження: у моєму `opencode.json` стоїть глобальне `"edit": {"*": "allow"}`, а блоку `agent.plan` з `"edit": "deny"`, `"bash": "deny"` немає — за методичкою це знову відкриває Plan для редагування, тож «лише читання» в Plan не гарантоване налаштуванням; контроль — журнал планувальної сесії і `git status --short`. | **Потрібна адаптація:** режим плану вмикається через `/plan`; після перегляду плану — `Yes, implement this plan`, і Codex переходить у звичайний режим і виконує зміни. |
| Журнал | **Потрібна адаптація:** окремий плагін `.opencode/plugins/agent-log.js` (подія `tool.execute.after`) пише у `.agent-log/opencode.jsonl`. У журналі видно виклики інструментів, зокрема `skill`, команди та інші дії агента. | **Потрібна адаптація:** `.codex/hooks.json` (подія `PostToolUse`) викликає `scripts/agent-log-hook.mjs`, рядки йдуть у `.agent-log/codex.jsonl`; hook потребує довіри в `/hooks`. Обмеження: `PostToolUse` у Codex спрацьовує і після команди з ненульовим кодом виходу, тож `result: "ok"` там не гарантує успіху (на кроці 03 помітила команду з `exit 1`, записану як `ok`). |
| Навичка | **Працює без змін:** OpenCode читає навичку прямо з `.claude/skills/` (також підтримує `.agents/skills/`). Автоматично викликав `add-api-route` для задач зі створення API-маршрутів: 3/3 позитивних запитів викликали навичку, 3/3 негативних (сторінки, компоненти, стилі) — ні. | **Потрібна адаптація:** Codex читає лише `.agents/skills/`, тому навичку скопійовано туди через `npm run sync-skills` (джерело — `.claude/skills/`). Codex бачить `add-api-route` у `/skills` і для API-задач читає `add-api-route/SKILL.md`: 3/3 позитивних запитів активували навичку, 3/3 негативних — ні. |
| Заборона | **Потрібна адаптація:** permission-маски в `opencode.json` (маски не бачать bash) плюс плагін `.opencode/plugins/guard-env.js` (`tool.execute.before`), який блокує доступ до `.env` і сам записує `result: "denied"` у `.agent-log/opencode.jsonl`. Реальними тестами підтверджено всі три способи: `edit`, shell-переадресацію та `node -e`; окремо — блокування читання `.env`. Виявлено обмеження текстового фільтра для динамічно сформованих шляхів; описано в журналі автономності. | **Не підтримується в моїй конфігурації:** `PreToolUse` у `.codex/hooks.json` під час практичної перевірки не заблокував запис, тому експериментальну конфігурацію прибрано, а `PostToolUse` для журналювання відновлено. **Чим замінили:** текстове правило в `AGENTS.md` («`.env` і `.env.local` агент не читає і не редагує») і режим підтвердження команд Codex (Default) — без автоматичного рядка `denied`. Обов'язкова заборона з рядком `denied` у журналі реалізована в OpenCode (методичка вимагає її щонайменше в одному інструменті). |
| MCP | **Потрібна адаптація:** Context7 підключено через ключ `"mcp"` в `opencode.json` (файл проєкту, без API-ключа). Реальні виклики `context7_resolve-library-id` і `context7_query-docs` підтверджено журналом; розмір відповідей — 2046 і 3299 символів (разом 5345). | **Потрібна адаптація:** Context7 підключено глобально в `~/.codex/config.toml` з авторизацією OAuth (поза репозиторієм). ### Перевірка скріншота

Скріншот `home-health-link.png` отримано із завантаженого артефакту GitHub Actions `playwright-artifacts`, після чого його скопійовано в репозиторій під назвою `docs/lab1/e2e-home.png`.

Зображення відкрито та перевірено візуально. На ньому видно:

- заголовок «Агентна інженерія»;
- підзаголовок «Стартовий шаблон»;
- підказку «Ваше завдання: додати ендпоінт /api/health»;
- нове посилання «Стан сервісу».

Тест не залежить від конкретного ШІ-агента, тому його можна запускати як після змін OpenCode, так і після змін Codex без адаптації тестового коду.

Оскільки артефакти GitHub Actions зберігаються обмежений час (у цьому шаблоні — 7 днів), копію скріншота залишено в `docs/lab1/` для подальшого захисту лабораторної роботи.
