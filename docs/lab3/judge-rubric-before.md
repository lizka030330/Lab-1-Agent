# Рубрика «до» ітерації (крок 05)

Один вимір — один суддя. Суддя бачить лише докази свого виміру. Вердикти: pass, fail, unknown.

## acceptance_met
- pass: у доказах видно, що кожна команда приймання стосується цієї зміни і завершилася кодом 0. Приклад: run.json має всі exit 0 і acceptance_passed true.
- fail: видно команду з кодом не 0 або зміна не стосується жодної з команд. Приклад: run.json має exit 1 для `test -f` або exit_status timeout.
- unknown: вивід обрізаний або в артефакті немає результату команд. Приклад: у run.json немає блоку acceptance.

## scope_respected
- pass: усі файли в patch.diff є в переліку files задачі. Приклад: patch.diff змінює src/metrics.ts, а files = [src/metrics.ts, tests/metrics.test.ts].
- fail: є файл поза переліком files. Приклад: patch.diff змінює src/auth.ts, якого немає в files.
- unknown: перелік files порожній, тому порівнювати ні з чим. Приклад: files = [].

## reason_stated
- pass: фінальний текст агента пояснює причину зміни, а не лише перелік файлів. Приклад: агент написав, чому додав функцію і які тести перевірив.
- fail: фінальний текст переказує diff або є порожнім при завершеному запуску. Приклад: текст містить лише список файлів.
- unknown: у доказах немає фінального тексту агента. Приклад: output.txt не містить текстового блоку.
