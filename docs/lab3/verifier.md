# Крок 02 — верифікатор як остання брама

**Пара:** агент — Gemini 3.6 Flash (OpenCode 1.18.34, `google/gemini-3.6-flash`) → верифікатор — Qwen3 8B локально в Ollama (`ollama/qwen3-8b-16k`, контекст 16k). Брама **локальна**: у GitHub Actions Ollama немає, тому `npm run verify:harness` запускаю перед злиттям гілки агента, після зелених брам кроку 01.

## Чому інша родина

Спершу в `factory.md` я записала верифікатором `gemini-3.5-flash-lite` з Лаб. 2 — «інша модель». Але це та сама родина Gemini, що й агент: спільні дані навчання — спільні сліпі плями, суддя схвалює те, що агент вважає правильним. Тому — Qwen (Alibaba), інша родина і інший постачальник. Плата: суддя слабший (8B) і повільніший (≈ 70–210 с на прогін), зате $0 і без квоти.

## Як влаштовано (`scripts/harness/verify-run.ts`)

| Вимога | Як зроблено |
|---|---|
| Суди лише за доказами | у запит іде дослівна задача, `patch.diff` агента (через `filterDiff`, перевірка на ключі `findSecret`) і коди виходу команд приймання; слова агента не передаються |
| Один суддя — один критерій | окремий запит на кожен критерій з `docs/lab3/criteria.jsonl` (2–4 на задачу) |
| Строга схема | `{id, verdict: pass|fail|unknown, reason, evidence}` (zod); `id` має збігатися з критерієм, для pass/fail `evidence` обовʼязковий |
| Невалідна відповідь | перепитує **рівно раз** із конкретною причиною, потім — помилка і ненульовий код |
| Що блокує | **усе, що не pass** (`isBlocked`): fail і unknown. У Лаб. 2 блокував лише fail (`isBlockedFailOnly` лишився для `scripts/verify.ts`) |
| Економія | якщо брами кроку 01 не зелені (`acceptance_passed` + усі `gates` pass), суддю не запускаю |
| Сліди | вердикт кожного прогону — `docs/lab3/verdicts/<прогін>.json` (модель, час, мс, усі вердикти) |

Брама «закрита за замовчуванням»: зламана відповідь судді блокує зміну, а не пропускає її. Таке було двічі:

1. **14.11, калібрування.** Qwen двічі повернула `"id": "t-01"` (номер задачі) замість `"C1"` — скрипт зупинився з помилкою. Виправлення — у запиті явно сказано, що `id` рівно `C1`, повторний запит називає причину; схему не послаблювала.
2. **15.11, t-11, C3.** Двічі поспіль невалідний JSON: після рядка `evidence` зайва `)` (`… { ... }")}`). Вердикт не записано, код виходу ненульовий — зміна вважалась неперевіреною. Повторний запуск судді через 3 хв дав валідні вердикти (pass за всіма 4).

## Справжня зупинка

**Не отримала.** На 13 зелених прогонах (11 задач, дві моделі агента, 13–16.11) агент жодного разу не порушив критерій, який не перевіряють команди, — і суддя жодного разу не зупинив зміну. Я перевірила кожен вердикт за diff сама і з усіма 13 згодна. Підробляти зупинку (навмисно зіпсувати diff агента чи дописати критерій під готовий прогін) не стала: це фальсифікація доказу.

Задачі я поступово ускладнювала, щоб дати верифікатору шанс: t-08, t-09 — критерії «код не змінено», «очікування відповідають реалізації»; t-10, t-11 — зміна **наявного** коду; t-12, t-13 — явні вимоги (українські назви, «лише через `isRefusal`», `Math.round`), яких команди не перевіряють. Агент виконав усі.

Що суддя вміє зупиняти, видно з калібрування на справжніх змінах агента:

| Прогін | Що порушив агент | Суддя | Чому в режимі брами до судді не дійшло |
|---|---|---|---|
| t-01-1794565498582 | переписав наявну `mean` (C4) | **fail** | acceptance fail (дубль `mean` ламає typecheck) |
| t-02-1794564828130 | немає імпортів vitest (C1), тест очікує однобуквені токени (C2) | **fail**, **fail** | acceptance fail (тест падає) |

Тобто на цих прогонах порушення були справжні, і суддя їх бачить, але дешеві детерміновані брами зупинили зміну раніше — так і задумано порядком «спершу брами, потім суддя». А пропущене порушення (випадок 3, хибний pass) показує, що суддя на 8B схильний до поблажливості: йому не можна бути єдиною брамою.

## Висновок

- Пара агент Gemini → суддя Qwen: інша родина, $0, без квоти; ціна — 37–210 с на прогін і поблажливість (1 хибний pass з 4 fail у калібруванні).
- κ = 0.811 при сирій згоді 0.929: довіряти можна, але не сліпо.
- Брама закрита за замовчуванням: двічі зламаний формат судді заблокував зміну.
- Економія: на 13 не зелених прогонах суддю не викликано жодного разу — 38 запитів (27 + t-05 3 + t-03 3 + t-04 2 + t-13 3).
- Справжньої зупинки зеленої зміни немає — чесно, без підробки.
