# Мультимодальність у продукті

## Роль у продукті
- **Що робить мультимодальний шлях:** «фото сторінки або PDF → відповідь із номером сторінки, і за бажанням — озвучена». Користувач завантажує документ і питає; асистент відповідає лише за вмістом файлу у форматі «Відповідь: … / Сторінка: N», а якщо відповіді у файлі немає або файл нечитабельний — «не знаю», без вгадування. Код: `src/multimodal/`, `app/api/multimodal/route.ts`, сторінка `app/multimodal/page.tsx`.
- **Задеплоєний застосунок:** https://lab-1-agent-git-lab4-step-00-efremka.vercel.app/multimodal — preview гілки `lab4/step-00` (коміт `77af39b`), захищений Vercel Authentication; для скрипта прогону — заголовок `x-vercel-protection-bypass` із секретом «Protection Bypass for Automation» (з оточення, ніде не записаний).
- **Що застосунок робить, коли файл непридатний:** тип поза білим списком → 415 і повідомлення «Тип … не підтримується. Можна: PNG, JPEG, WEBP, HEIC/HEIF або PDF»; файл понад 3 МБ → дружня відмова **в браузері** без запиту, а на сервері — 413 зі своїм повідомленням; заявлений тип не збігається з вмістом → 415 «заявлено як …, а за вмістом це …»; нечитабельний або без відповіді → «Відповідь: не знаю».

## Генерація зображень — поза межами, і чому
Безкоштовного шляху до генерації зображень у джерелах курсу не підтверджено в жодного провайдера: у всіх перевірених моделей зображень Google у колонці Free Tier стоїть «Not available». `generateImage` в ai@7 існує і НЕ є експериментальною, але прогнати її за нуль неможливо. Тому крок будується на вході (зображення, PDF) плюс синтезі мовлення.

## Вхід
- Частина повідомлення: `FilePart` — `{ type: 'file', mediaType, filename, data: { type: 'data', data: bytes } }`, `mediaType` обовʼязковий; застаріла `ImagePart` не використовується (`src/multimodal/ask.ts`).
- Форма data: `{ type: 'data' }` (сирі байти) — файл приходить у функцію формою і більше ніде не зберігається; `{ type: 'url' }` потребував би публічного сховища, `{ type: 'reference' }` (uploadFile) — для файлів понад ліміт, у цьому кроці не реалізовано.
- Медіатип **визначається за вмістом**: `detectMediaType` з `@ai-sdk/provider-utils` (без `topLevelType` — усі сигнатури); заявлений клієнтом тип, що не збігається, — відмова `mismatch` (випадок mm-11). HEIC/HEIF у білому списку, але сигнатуру HEIC `detectMediaType` може не впізнати — тоді такий файл буде відхилено як `mismatch` (не перевіряла: HEIC-файлу в наборі немає).
- Білий список: `image/png`, `image/jpeg`, `image/webp`, `image/heic`, `image/heif`, `application/pdf` (`ALLOWED_MEDIA_TYPES`, `src/multimodal/limits.ts`).
- Модель: `gemini-3.8-flash` (з реєстру `src/models.ts`; мій ключ — платний Tier 1, тож «Free of charge» тут не обмеження, а орієнтир).

## Вихід
- Функція: `generateSpeech` (НЕ експериментальна; `experimental_generateSpeech` — застарілий аліас) — озвучення відповіді за галочкою «озвучити відповідь»; для перевірки round-trip ще й `transcribe` (`src/multimodal/speak.ts`).
- Моделі: `gemini-3.8-flash-tts` (мовлення) і `gemini-3.5-transcribe` (транскрипція) — обидві є в переліку провайдера `@ai-sdk/google` 4.0.87.
- `voice` / `outputFormat` / `language` **не задавала** (курс не називає допустимих значень): типово повернулося `audio/wav`, ≈ 250 КБ на речення, синтез ≈ 3,3 с; `transcribe` повернув `language: null` і `durationInSeconds: null` — провайдер цих полів не повідомив.

## Межі й поведінка при перевищенні
| Що | Межа Gemini | Межа функції Hobby | Що робить застосунок (перевірено на задеплоєному, 25.11.2026) |
|---|---|---|---|
| розмір запиту | 20 MB інлайн | 4,5 MB тіло → 413 FUNCTION_PAYLOAD_TOO_LARGE | > 3 МБ: браузер відмовляє сам (без запиту); сервер — 413 зі своїм повідомленням (mm-09: 4,0 МБ); > 4,5 МБ — 413 від **платформи**, мій код не виконується (mm-10: 6,7 МБ, `x-vercel-error: FUNCTION_PAYLOAD_TOO_LARGE`) |
| PDF | 50 MB або 1000 стор.; 258 токенів/стор. | 4,5 MB | приймається до 3 МБ; відповідь із номером сторінки (mm-02, mm-03) |
| зображення | до 3 600 на запит; 258 токенів (≤ 384 px) або плитки 768×768 | 4,5 MB | приймається до 3 МБ PNG/JPEG/WEBP/HEIC/HEIF; TIFF — 415 (mm-08) |
| аудіо | 9,5 год; 32 токени/с | 300 с → 504 FUNCTION_INVOCATION_TIMEOUT | аудіо на вхід не приймається; на виході — коротке озвучення відповіді (`maxDuration = 60` с у маршруті) |
| обхід | Files API: 20 GB/проєкт, 2 GB/файл, 48 год, без оплати | — | не реалізовано: файли понад 3 МБ відхиляються з порадою стиснути зображення або розбити PDF |

**Мій клієнтський ліміт: 3 000 000 байтів** (`MAX_BYTES`, `src/multimodal/limits.ts`) — одна константа для браузера й сервера. Файл іде як `multipart/form-data`, тобто без base64; запас до 4,5 МБ лишено на поля форми й на випадок переходу на JSON із base64 (+≈1/3: 3 МБ → 4 МБ).
Розбіжність у документації, яку я не вирішую: сторінка Files API радить її при понад 100 MB і згадує 50 MB для PDF, сторінки зображень і аудіо називають 20 MB сумарно. Безпечною інлайн-стелею вважаю 20 MB; на практиці моя стеля — 4,5 MB тіла функції.

## Квота — моє власне число
Документація лімітів безкоштовного рівня не публікує; сторінка обмежень частоти відсилає до AI Studio. Мій ключ — **платний Tier 1**.
- Що показує моя сторінка AI Studio → Usage & Billing → **Rate Limit** (проєкт «Default Gemini Project», **Tier 1**; формат «пік використання за 28 днів / ліміт»):

| Модель | RPM | TPM | RPD | роль у моєму продукті |
|---|---|---|---|---|
| Gemini 3.8 Flash | 29 / **1K** | 172,97K / **2M** | 558 / **10K** | вхід (зображення, PDF), кроки 03–04 |
| Gemini 3.8 Flash TTS | 2 / **10** | 55 / **10K** | 3 / **100** | озвучення відповіді |
| Gemini 3.5 Transcribe | 2 / **10** | 516 / **10K** | 2 / **100** | транскрипція (round-trip) |

- Дата, коли я це переписала: **25.11.2026**, 22:29.
- Висновок для архітектури: **найвужча стеля — мовлення, а не вхід**: 10 запитів за хвилину і 100 за день на TTS проти 1 000 / 10 000 на Flash. Озвучення тому за галочкою (типово вимкнене), і саме його обмежує правило частоти в кроці 06. Скріншот сторінки в репозиторій не кладу — на ньому видно мою пошту.
