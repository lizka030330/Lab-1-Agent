## 1. План (заповнено ДО першого рядка коду, дата: 2026-11-24)
- Обраний шлях: `git revert`
- Чому саме він: зміна — один звичайний коміт (не злиття) в одному файлі реалізації `src/index.ts`, без нових залежностей і без змін `package.json`/lock-файла; revert додає коміт-скасування, тому в історії форка видно і зміну, і відкот. Прапорець чи конфігурація означали б новий публічний параметр у чужому проєкті — це вже зміна API, а не відкот.
- Команда дослівно: `git revert --no-edit <sha-коміта-зміни>` на окремій гілці `lab4/rollback-drill` (SHA підставляю руками з `git log --oneline -5`; коміт нового тесту НЕ відкочую)
- Ознака, що відкот потрібен (будь-яка з них):
  - `npx vitest run src/characterization.spec.ts` → код виходу ≠ 0 (зламано зафіксовану поведінку кроку 01);
  - `npm test` → код виходу ≠ 0, зокрема через `size-limit`: зараз 1.84 kB при межі 2 kB (`reports/lab4/npm-test-after-char.log` у форку) — більша функція декодування може межу перевищити;
  - тип помилки змінився (не `URIError`) або для коректного %-кодування `match()` почав кидати помилку.
- Чого відкот НЕ повертає: файл нового тесту (`src/decode-error.spec.ts`) — він у окремому коміті ПЕРЕД зміною і лишається; після відкоту він має стати червоним. Залежностей і згенерованих файлів зміна не додає.
- Скільки це займає: оцінка ≤ 5 хв (одна команда revert + прогін двох тестових файлів + `npm test`); фактичне число — у розділі 2.
