# q1: Що робить match() у src/index.ts, коли значення параметра має бите %-кодування, які тести проєкту стосуються декодування і коли src/index.ts востаннє змінювали?

У функції match() у файлі src/index.ts за замовчуванням опція декодування використовує стандартну функцію decodeURIComponent. Під час зіставлення шляху значення знайдених параметрів передаються до декодера без огортання в блок try/catch. Відповідно, якщо значення параметра містить некоректне або бите %-кодування, виклик decodeURIComponent завершується викидом необробленої помилки URI malformed. Якщо ж користувач явно передає опцію зі значенням decode: false, декодування не виконується, і значення повертаються у сирому вигляді без помилок. Тестування процесів декодування зосереджене головним чином у файлах src/characterization.spec.ts, src/cases.spec.ts та src/index.spec.ts. Зокрема, файл src/characterization.spec.ts містить окремі тести як для успішного одноразового декодування параметрів, так і для перевірки викиду помилки URI malformed у разі битого %-кодування в звичайних параметрах та wildcard. Крім того, у src/cases.spec.ts наявні сценарії для перевірки опції decode: false, які запускаються через параметризований набір у src/index.spec.ts. Що стосується історії змін, то файл src/index.ts востаннє змінювали 2026-11-21 у коміті commit:c439054 із повідомленням «Escape with a lookahead insert (#465)».
