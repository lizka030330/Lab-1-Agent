# q3: Які символи parse() не дозволяє в шаблоні без екранування, який клас помилки кидається і де це перевіряють тести?

Під час аналізу шаблону функція parse() забороняє використовувати без екранування символи }, (, ), [, ], +, ?, !. Якщо парсер натрапляє на один із цих символів без попереднього екранування зворотним слешем, він перериває роботу. Крім того, забороняється залишати неекранований зворотний слеш \ у кінці рядка або групи без наступного символу. Символи двокрапки : та зірочки * не дозволяються без валідного імені параметра або без належного закриття подвійними лапками. Відкриваюча фігурна дужка { також вважається помилкою, якщо вона не має відповідної закриваючої дужки. У разі виникнення будь-якої з цих синтаксичних проблем викидається спеціальний клас помилки PathError, який успадковує стандартний TypeError. Перевірка неприпустимих символів }, (, ), [, ], +, ?, ! реалізована у тестовому файлі src/index.spec.ts за допомогою параметризованого тесту it.each. Інші пов'язані помилки парсингу (незакриті лапки, відсутність імен параметрів після : чи *, висячий \ та незакриті групи) також тестуються в наборі describe("parse errors") цього ж файлу.

## Твердження (усі pass у верифікатора qwen3-8b-16k)
- c1: Для синтаксичних помилок розбору parse() кидає власний клас PathError, що розширює TypeError. — `src/index.ts#L128-L139`
- c2: У тілі parse() за умови if ("}()[]+?!".includes(char)) кидається помилка на неекрановані символи }, (, ), [, ], +, ?, !. — `src/index.ts#L229-L231`
- c3: Символ зворотного слеша \ заборонено залишати останнім у рядку або групі без наступного символу для екранування. — `src/index.ts#L170-L176`
- c4: Символи : та * без коректного імені параметра або закритих лапок призводять до помилки парсингу. — `src/index.ts#L211-L213`
- c5: Символи }, (, ), [, ], +, ?, ! перевіряються параметризованим тестом it.each у тестовому наборі. — `src/index.spec.ts#L111-L118`
- c6: Помилка висячого зворотного слеша наприкінці рядка перевіряється в тестах блоку eol backslash. — `src/index.spec.ts#L81-L109`
