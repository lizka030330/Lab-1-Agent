# q1: Що робить match() у src/index.ts, коли значення параметра має бите %-кодування, які тести проєкту стосуються декодування і коли src/index.ts востаннє змінювали?

За замовчуванням функція match() у src/index.ts застосовує стандартну функцію decodeURIComponent для обробки значень параметрів. Оскільки виклик декодера у повернутій функції виконується напряму без конструкції try/catch, передача рядка з битим %-кодуванням призводить до викидання помилки "URI malformed". Уникнути цього винятку можна лише передачею власного декодера або вимкненням обробки за допомогою опції { decode: false }. Поточна поведінка для битого %-кодування зафіксована у тестах src/characterization.spec.ts як для звичайних параметрів, так і для wildcard. Крім того, тести у src/characterization.spec.ts перевіряють штатне декодування валідних значень та роботу опції decode: false. Різні кейси з %-кодованими рядками та відключеним декодуванням також представлені у файлі src/cases.spec.ts, а параметризовані тести match проганяються у src/index.spec.ts. Сам файл src/index.ts востаннє змінювали 2026-11-21 у коміті c439054.
